# Сайт Михаила Савцова и SEO-агент статей

Статичный сайт (главная, статьи, карта сайта, разметка для поисковиков) и агент, который три раза в день пишет статью через Claude API и отдаёт её на проверку.

## Как это работает

1. Каждый день около 09:23, 13:17 и 17:41 по Новосибирску (GitHub может задержать запуск) GitHub Actions (`.github/workflows/article.yml`) берёт следующую тему со статусом `todo` из `agent/topics.csv`.
2. Дешёвая модель (`RESEARCH_MODEL`, Haiku) ищет источники в интернете (обзоры, мета-анализы, исследования, ACSM, ISSN и т.п.) и собирает выжимку фактов со ссылками. Связанные запросы из колонки `related` в `topics.csv` подсказывают, какие подвопросы раскрыть.
3. Основная модель (`MODEL`, Opus) пишет статью по выжимке и правилам `agent/style.md` (инфостиль, словарь Михаила, без призывов и медицинских обещаний) и `agent/seo.md`. Местные детали (клуб, Новосибирск, истории Михаила) берёт только из `agent/local.md`; вопросы, по которым Михаил его пополняет, — в `agent/local-questions.md`.
4. `agent/seo.py` проверяет длину H1, title и description, запретные фразы, главный запрос в H1 и первом абзаце, повтор запроса в подзаголовках и FAQ, разделы, объём, ссылки и качество источников. Ошибки правит один короткий вызов модели, замечания попадают в описание PR.
5. При `AUTO_PUBLISH=true` статья сразу уходит на сайт. Иначе она приходит запросом на слияние (Pull Request) `Статья: …` и сливается сама, если сайт собирается (см. «Правки сайта сливаются сами»).

Расход пишется в `agent/usage.csv`. Агент останавливается, если за месяц потрачено больше `MONTH_LIMIT_USD` (по умолчанию $70: три статьи в день по ~$0,65 — около $60 за месяц). Сколько статей в день, задаёт переменная `ARTICLES_PER_DAY` (по умолчанию 3).

## Что нужно один раз

1. **Cloudflare.** dash.cloudflare.com → Workers & Pages → Create → Import a repository → `fit-site`.
   Имя проекта: `fit-site` (должно совпадать с `name` в `wrangler.jsonc`). Build command: `pip install -r requirements.txt && python3 build.py`. Deploy command: `npx wrangler deploy` (по умолчанию). Сайт раздаётся из `public/` по настройкам `wrangler.jsonc`.
   Адрес вида `fit-site.<аккаунт>.workers.dev` записать в `site.json` → `base_url`. Свой домен: проект → Settings → Domains & Routes.
2. **Ключ Claude API.** platform.claude.com → API Keys → Create key. Положить в GitHub: Settings → Secrets and variables → Actions → New repository secret, имя `ANTHROPIC_API_KEY`. В консоли Anthropic стоит поставить лимит расходов: Settings → Limits.
3. **Разрешить агенту создавать запросы на проверку.** Settings → Actions → General → Workflow permissions → Read and write permissions и галочка «Allow GitHub Actions to create and approve pull requests».
4. **Поисковики.** Яндекс Вебмастер и Google Search Console: добавить сайт, код подтверждения вписать в `site.json` (`yandex_verification`, `google_verification`), затем отправить `https://<адрес>/sitemap.xml`. Яндекс Метрика — номер счётчика в `yandex_metrika_id`. Google Analytics 4 — идентификатор вида `G-XXXXXXX` в `google_analytics_id`. Нажатия на кнопки связи уходят в оба счётчика как цели `click_phone`, `click_telegram`, `click_max`, `click_whatsapp` (в Метрике создать цели типа «JavaScript-событие» с этими идентификаторами).

## Правки сайта сливаются сами

Workflow `.github/workflows/auto-merge.yml` сам нажимает **Merge** в запросах на слияние (PR) из веток `claude/…` (правки, которые делает Claude) и `article/…` (статьи, если выключен `AUTO_PUBLISH`). Условие: сайт собирается (`python3 build.py`). Через минуту после слияния сайт обновляется.

Сам не сливается:
- черновик (Draft). Попросите Claude: «покажи перед слиянием», и он откроет PR черновиком. Проверили, нажали **Ready for review** — PR сольётся сам;
- PR с меткой **проверю сам** (справа в PR → Labels). Сняли метку — PR сольётся сам;
- PR, который меняет папку `.github/` (сами автоматизации). Такие PR сливаются только вручную.

Отменить слитую правку: в PR кнопка **Revert**, затем Merge.

## Картинки в статьях

Под каждым подзаголовком статьи стоит SVG-картинка. Opus описывает, что показать (поза скелета с работающими мышцами, график, диапазон, сравнение, чек-лист, шаги), а рисует `agent/figures.py` на общем наборе `agent/svgkit.py`, поэтому стиль у всех картинок один, а тёмная тема работает сама. Файлы лежат в `static/img/<slug>/`. Это добавляет к статье примерно $0,1.

К каждому упражнению, технику которого описывает статья, отдельно рисуется схема скелета с мышцами: начальная поза бледно, конечная ярко, стрелка движения, внизу — какие мышцы работают. Схема встаёт после абзаца или списка с описанием (`move-NN.svg`). Готовые позы — `EXERCISES` в `agent/moves.py` (лёжа, мостик, «птица-собака», планки и др.), любое другое упражнение без снаряда модель задаёт углами суставов.

К уже вышедшим статьям картинки дорисовывает workflow **add-figures** (Actions → add-figures → Run workflow; пустой slug — все статьи, где их не хватает). Схемы к статье про присед нарисованы вручную: `tools/squat_svg.py`.

## Фото в статьях

1. **Свои фото — лучший вариант**: и для доверия, и для поиска по картинкам. Кладите их в `content/photos/` и описывайте одной строкой в `content/photos/photos.csv` (подробно в `content/photos/README.md`). Подойдут стоп-кадры из Reels. Агент сам выбирает фото по теме для обложки и для текста.
2. **Бесплатный фотосток Pexels**: включается, если своего фото по теме нет. Ключ бесплатный: pexels.com/api → Get Started. Положите его в секрет `PEXELS_API_KEY`. Под фото агент указывает автора.

## Настройки (Settings → Secrets and variables → Actions → Variables)

| Переменная | Что делает | По умолчанию |
|---|---|---|
| `MODEL` | модель, которая пишет текст: `claude-opus-5-5` (лучше текст) или `claude-sonnet-5-5` (дешевле примерно вдвое) | `claude-opus-5-5` |
| `RESEARCH_MODEL` | модель для поиска источников | `claude-haiku-5-5` |
| `MONTH_LIMIT_USD` | потолок расходов в месяц | `70` |
| `ARTICLES_PER_DAY` | сколько статей в день пишут запуски по расписанию | `3` |
| `AUTO_PUBLISH` | `true` — публиковать без проверки | проверка включена |

## Темы

`agent/topics.csv`: одна строка — один поисковый запрос. Колонки: `keyword`, `status` (todo/done), `slug`, `cluster`, `category` (тема на сайте, slug из `categories` в `site.json`; пусто — тему выберет модель), `related` (связанные подсказки через `|`). Если по запросу статья уже есть, агент закрывает тему и берёт следующую. Порядок строк — очередь. Лучше брать запросы из Яндекс Wordstat (wordstat.yandex.ru): реальные формулировки людей, с частотой от 50–100 показов в месяц.
Написать статью прямо сейчас или по своей теме: Actions → write-article → Run workflow → поле «Запрос».

## Темы статей на сайте

Список тем — `categories` в `site.json` (slug, название, описание). У каждой статьи в шапке поле `category`. Сборка делает страницу `/stati/<slug>/` для каждой темы, где есть статьи, ряд тем над списком статей, метку темы на карточках и ссылку на тему в «хлебных крошках» статьи. Новая тема: добавить строку в `categories`; адрес темы не должен совпадать с адресом статьи.

## Семантическое ядро

`agent/semantic_core.csv` — все запросы сайта: кластер, тип (коммерческий — страница услуги, информационный — статья), адрес страницы, приоритет, источник (подсказки Яндекса по Новосибирску и Google). Главный запрос страницы помечен `main=да`.
Очередь статей в `agent/topics.csv` собрана из этого ядра: сначала спина, похудение, диастаз, травмы, осанка и набор массы, потом общие темы про тренировки. В `related` лежат связанные подсказки для подзаголовков и FAQ.
Обновить подсказки: добавить затравки в `agent/semantic/seeds.txt` и запустить `python3 agent/semantic/collect.py` (нужен доступ к suggest.yandex.ru и Google), сырые подсказки лягут в `agent/semantic/suggest_raw.csv`.

## Править руками

- Главная: `content/pages/home.md` и `site.json`.
- Отзывы на главной: `site.json` → `reviews`, список вида `{"name": "Анна", "goal": "минус 6 кг за 4 месяца", "text": "..."}`. Пустой список — блока нет. Только настоящие отзывы с согласия клиента.
- Статья: `content/articles/<slug>.md`. Сверху JSON с заголовком, описанием, FAQ и источниками, ниже текст в Markdown. Скрыть статью: `"draft": true`.
- Проверить сборку локально: `pip install -r requirements.txt && python3 build.py`, сайт появится в `public/`.

## Сколько стоит

Первая статья, где и поиск, и текст делал Opus, стоила $2,52: при поиске модель прочитала почти 500 тысяч токенов страниц. Теперь поиск делает Haiku, и ожидаемая цена статьи около $0,5–0,8. Точные цифры — в `agent/usage.csv`.
При одной статье в день $100 хватает примерно на 5–8 месяцев на Opus и на год на Sonnet. Хостинг Cloudflare Pages и GitHub Actions бесплатные.
